🏭 Factory Inventory Management System

System Architecture & Technical Documentation

Project Overview

A full-stack demo application for managing factory inventory, orders, demand forecasting, and spending analysis. Built with modern web technologies and designed for real-time data visualization.

Key Characteristics:
  • Real-time data filtering across 6 distinct views
  • In-memory mock data (no persistent database)
  • Multi-language support (English, Japanese)
  • RESTful API with Pydantic validation
  • Interactive dashboard with advanced charting

Request Flow Details

1. User Input: User selects filters (time period, warehouse, category, status)

2. State Update: Filters stored in useFilters composable

3. HTTP Request: View component calls API via api.js with filter params

4. Backend Processing: FastAPI endpoint applies filters to in-memory data

5. Response: Pydantic model serializes to JSON

6. Rendering: Vue component displays filtered data in table/charts

Global Filtering System

Filter Types:
  • Time Period: Month or Quarter selection
  • Warehouse: Distribution center location
  • Category: Product category
  • Order Status: Delivered, Shipped, etc.

Implementation Pattern

Frontend: - FilterBar.vue displays filter controls - useFilters.js manages global state - Each view subscribes to filter changes - API calls include filter params Backend: - Query params: ?warehouse=Chicago&category=Electronics&status=Delivered - Filtering logic: list comprehensions with 'all' checks - Month/Quarter parsing: supports "2025-01" or "Q1-2025"

Shared State Management (Composables)

Composable Purpose Exports
useFilters.js Global filter state selectedPeriod, warehouse, category, status, reset()
useAuth.js User & mock auth data currentUser, tasks, profile data
useI18n.js Internationalization t() function, currency, language toggle

Key Design Patterns

Frontend Patterns

  • Composition API: Feature-based organization
  • Composables: Reusable logic extraction
  • Centralized API: Single api.js entry point
  • Reactive Refs: State management
  • Computed Properties: Derived data
  • Modal System: Detail view triggers

Backend Patterns

  • RESTful Design: Plural nouns, proper HTTP
  • Query Param Filtering: Flexible composition
  • Pydantic Models: Type safety & validation
  • In-Memory Data: JSON files at startup
  • Stateless: No session management
  • CORS Enabled: Development mode
