Factory Inventory Management System

Complete Architecture & System Overview

🏗️ System Architecture

🖥️
Frontend Layer

Vue 3 + Composition API + Vite

Client-side SPA running on http://localhost:3000

Handles UI rendering, user interactions, state management, and API communication through centralized axios client.

⚙️
Backend Layer

Python FastAPI with Uvicorn

REST API server running on http://localhost:8001

Handles business logic, data validation (Pydantic), filtering, aggregation, and serves API endpoints with automatic Swagger documentation.

📊
Data Layer

In-Memory Mock Data

JSON files stored in server/data/ and loaded at startup

No database required for demo. Data persists in memory during runtime but reloads from files on server restart.

Key Characteristic:

This is a full-stack demo application with a clean separation of concerns. The frontend communicates exclusively through REST API calls, making it easy to swap the backend without changing the UI code.

📈 Data Flow

1

User Interaction (Frontend)

User selects filters or navigates to different views in the Vue 3 UI

2

Filter Management (Composables)

Filters stored in useFilters() composable, triggering reactive updates

3

API Request (client/src/api.js)

Axios client constructs query parameters and sends GET/POST requests to backend

4

Route Handler (FastAPI)

FastAPI route handler receives request and extracts query parameters

5

Data Filtering (Python)

In-memory data filtered by warehouse, category, status, month using Python list comprehensions

6

Pydantic Validation

Response data validated against Pydantic models before serialization

7

JSON Response (API)

FastAPI returns validated data as JSON with appropriate HTTP status code

8

Data Display (Frontend)

Vue component receives data, updates reactive refs, computed properties transform data for display

✨ Key Features & Patterns

Filter System

The application implements a 4-filter system that applies consistently across most views:

Time Period

Filter by month or quarter (Q1-2025 through Q4-2025)

Warehouse

Filter by warehouse location

Category

Filter by product category

Order Status

Filter by order status (Pending, Shipped, Delivered)

Reactivity Pattern

Frontend: Raw data stored in refs (allOrders, inventoryItems), derived data computed via properties

Backend: Data filtering happens server-side via Python functions, reducing client-side computation

API Communication

Centralized Client: All API calls route through client/src/api.js using Axios with consistent error handling

Query Parameters: Filters passed as URL query params, making API calls cacheable and bookmarkable

🚀 Development Workflow

Local Development Setup

Backend:
cd server && uv run python main.py
Runs on http://localhost:8001 with auto-reload enabled
Frontend:
cd client && npm run dev
Runs on http://localhost:3000 with Vite HMR (Hot Module Replacement)

API-First Design

Automatic Documentation
