Data Flow

Filters are the spine of the app: a single shared filter state drives every request.

FilterBar.vueuser picks period / warehouse / category / status
→
useFilters()singleton refs; getCurrentFilters()
→
src/api.jsaxios GET with query params
→
FastAPI routeapply_filters + filter_by_month
→
Pydantic modelvalidates & serializes response
→
View computed propsraw data in refs, derived values computed

Reads are filtered server-side against in-memory lists. Writes (tasks, purchase orders) POST/PATCH/DELETE and mutate the same in-memory lists — changes last only until the server restarts.

Key Conventions

Reactivity

Raw API data lives in refs (allOrders, inventoryItems); everything derived is a computed property. Filter state is a module-level singleton shared across views.

Time filtering

Months match YYYY-MM substrings of order_date. Quarters expand via QUARTER_MAP. Inventory has no time dimension, so month filters don't apply.

Validation

Every list endpoint declares a response_model; changing a JSON field means updating the matching Pydantic model in main.py.

Design system

Slate/gray palette, green/blue/yellow/red status colors, hand-rolled SVG charts, CSS Grid layouts, no emojis in the UI.
