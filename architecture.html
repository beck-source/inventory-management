Factory Inventory Management System

Architecture overview: a Vue 3 single-page app over a FastAPI service backed by in-memory JSON data (no database).

System architecture

Three tiers, all running locally. The browser talks to the API directly over HTTP.

Frontend

Vue 3 + Vite, localhost:3000
  • Views: Dashboard, Inventory, Orders, Demand, Spending, Reports
  • Components: FilterBar, detail modals, profile and language menus
  • Composables: useFilters, useI18n (en/ja), useAuth
  • API client: src/api.js (axios)
→HTTP / JSON
query params

Backend

FastAPI + Uvicorn, localhost:8001
  • Routes: inventory, orders, demand, backlog, dashboard, spending, reports
  • Filtering: apply_filters, filter_by_month (month or quarter)
  • Validation: Pydantic response models
  • CORS: open to all origins
→Python
import

Data

In-memory, loaded at startup
  • server/mock_data.py reads JSON once on import
  • server/data/*.json: inventory, orders, demand_forecasts, backlog_items, spending, transactions, purchase_orders
  • generate_data.py regenerates sample data

Data flow

What happens when a user changes a filter on a page.

  1. User changes a filterPeriod, warehouse, category or order status in FilterBar.
  2. Shared filter state updatesuseFilters holds the four filters as singleton refs, so every view sees the same values.
  3. View requests datagetCurrentFilters() builds the filter object; api.js drops values equal to all and sends the rest as query params.
  4. FastAPI filters in memoryThe route applies apply_filters and filter_by_month to the lists loaded from JSON.
  5. Response is validatedPydantic models shape the JSON before it is returned.
  6. UI re-rendersRaw data sits in refs; derived values (totals, chart series) are computed properties.

Endpoints and filter support

EndpointFilters

GET /api/demand, /api/backlognone
GET /api/spending/*none (summary, monthly, categories, transactions)
GET /api/reports/*none (quarterly, monthly-trends)

Inventory has no time dimension, so it ignores the month filter. Quarters (Q1-2025 to Q4-2025) expand to their three months on the server.

Observations

Things worth knowing before you change the code.

Client and server are not fully in sync

  • api.js calls /api/tasks (GET, POST, PATCH, DELETE) and POST /api/purchase-orders, but server/main.py defines no such routes, so those calls would return 404.
  • Backlog.vue exists but is not registered in the router in main.js; backlog data appears on the Dashboard instead.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js.
  • Data is read-only and in-memory, so any write would be lost on restart.
