📋 System Overview

A comprehensive factory inventory management system demonstrating a modern full-stack architecture. The system provides real-time visibility into inventory levels, order management, demand forecasting, spending analytics, and backlog tracking. Built with Vue 3 frontend and FastAPI backend, utilizing in-memory mock data for rapid prototyping and demonstration.

Status: Development/Demo Mode | Data: In-Memory Mock Data | Database: None (JSON-based)

🔄 Data Flow & Filtering

The system implements a cascading filter pattern where user selections flow from the UI through the API to the data layer.

Filter System (4 Dimensions)

📅 Time Period

All Months, Monthly, Quarters (Q1-Q4 2025) - Applies to orders and reports only

🏢 Warehouse

San Francisco, London, Tokyo - Applies to inventory and orders

📦 Category

Circuit Boards, Sensors, Actuators, Controllers, Power Supplies - Universal filter

🚚 Order Status

Processing, Backordered, Shipped, Delivered - Orders and dashboard only

Data Flow Pipeline

Vue Component (FilterBar) ↓ (emits filter changes) Composable (useFilters) ↓ (maintains filter state) API Client (client/src/api.js) ↓ (builds query params: ?warehouse=SF&category=Sensors) FastAPI Endpoint (server/main.py) ↓ (applies filters with helper functions) Filtered Results ↓ (Pydantic validation) JSON Response ↓ (Vue reactivity) Computed Properties (derived data) ↓ (rendered in templates) User Interface

Component Patterns

Composition API Pattern: 1. Define reactive state with ref() 2. Create computed properties from refs 3. Implement async data loading in try/catch 4. Watch filter changes to reload data 5. Return reactive state for template Reactivity Rules: ✓ Use .value in script for ref access ✓ No .value needed in templates (auto-unwrap) ✓ Use unique keys in v-for (never index) ✓ Validate dates before .getMonth() calls ✓ Emit events to communicate with parent

⚙️ Backend Architecture

API Design Pattern

Request Flow: 1. Client sends GET request with query parameters 2. FastAPI validates parameters 3. Pydantic models define request/response schema 4. Filter functions apply conditions to data 5. Results validated against Pydantic models 6. JSON response sent to client Filtering Pattern: - Check filter parameter for None or 'all' - Apply filters sequentially to list - Use lowercase comparison for case-insensitive matching - Don't mutate original data (filter on copies) - Return filtered list

🎯 Key Design Decisions

Why In-Memory JSON Data?

  • → Development Speed - No database setup required
  • → Easy Prototyping - Modify JSON files and restart
  • → Zero Dependencies - No database drivers or ORM
  • → Sufficient for Demo - <10K items load instantly into memory

Why Vue 3 Composition API?

  • → Better Organization - Group related logic together
  • → Reusable Logic - Extract logic into composables
  • → TypeScript Ready - Better type inference than Options API
  • → Smaller Bundle - Only import what you use

Why FastAPI?

  • → Modern Python Framework - Async support, type hints
  • → Built-In Documentation - Auto-generated Swagger UI
  • → Data Validation - Pydantic integration out of the box
  • → Easy Scaling - Database integration is straightforward

⚠️ Important Implementation Notes

Data Filtering Rules

  • • Inventory filters: warehouse, category (NO time/month dimension)
  • • Orders filters: warehouse, category, status, month/quarter
  • • Dashboard filters apply to calculated summaries (inventory value, order counts)

Vue 3 Best Practices

  • • Always use unique keys in v-for (use SKU, ID, month - NOT index)
  • • Validate dates before calling .getMonth() - can throw errors
  • • Use ref() for mutable state, computed() for derived data
  • • Always use .value in script, not in templates (auto-unwrap)

Backend Best Practices

  • • Update Pydantic models when JSON data structure changes
  • • Always use response_model in endpoint decorators for validation
  • • Check for 'all' string value in filters to skip that filter
  • • Filter on copies, never mutate original data lists
