Factory Inventory
Management System

A Vue 3 dashboard and a FastAPI service, joined by exactly one contract: four shared filters travel from a select element to a Python list comprehension and back. There is no database. Seven JSON files are read into memory once at import and never written to.

A-01

System architecture

Three tiers, two processes. The browser tier and the application tier are separate dev servers talking over CORS-open HTTP; the data tier is not a service at all, but module-level Python lists populated at import time.

A-03

Data flow — one filter change

This is the only interaction pattern in the app, and every view implements it the same way. Changing a single select in the filter bar runs all nine steps.

  1. A select changes in the filter bar client/src/components/FilterBar.vue

    Four v-model bindings: time period, location, category, order status.

  2. The write lands in shared module state client/src/composables/useFilters.js

    The four refs are declared at module scope, outside useFilters(). Every importer gets the same refs — a singleton store built from plain reactivity.

  3. Each mounted view's watcher fires views/Dashboard.vue · Inventory.vue · Orders.vue …

    Every view runs watch([period, location, category, status], loadData). Nothing is pushed; views pull for themselves.

  4. Filters are shaped for the wire getCurrentFilters()

    Renames as it goes: selectedLocation → warehouse, selectedPeriod → month. This rename is the seam where UI vocabulary becomes API vocabulary.

  5. The query string is assembled client/src/api.js

    Any value equal to 'all' is dropped rather than sent, so an unfiltered request carries no params at all.

  6. Requests go out in parallel Promise.all([...])

    The dashboard fans out four calls at once — summary, orders, inventory, backlog — and waits for the set.

  7. FastAPI filters in memory server/main.py — apply_filters() · filter_by_month()

    Sequential list comprehensions. Category and status match case-insensitively; warehouse matches exactly. Month accepts either 2025-03 or Q1-2025 via QUARTER_MAP.

  8. Pydantic validates the response response_model=List[...]

    The contract is enforced on the way out, so a JSON file that drifts from its model fails loudly at request time rather than silently in the UI.

  9. Raw data lands in refs; computed properties derive the rest allOrders · inventoryItems → computed()

    Metrics, chart series and status rollups are never stored — they recompute from the refs, which is why a single assignment updates the whole page.

A-06

Field notes

Things the file layout does not tell you. Read these before assuming a feature works end to end.

Client ahead of server

Six API methods have no route

api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem. None of /api/tasks or /api/purchase-orders exists in main.py. The calls 404; App.vue catches and logs, so the task list silently falls back to the hardcoded array in useAuth.js.

Unreachable

Backlog.vue has no route

The view is complete and imports api.getBacklog(), but main.js never registers it and no nav link points at it. Backlog data reaches users only through the table embedded in the dashboard.

Always false

has_purchase_order cannot be true

/api/backlog sets the flag by matching against purchase_orders.json, which is an empty array — and there is no write path to fill it.

By design

Nothing survives a restart

mock_data.py reads the JSON files once at import. Mutating the in-memory lists would work for the life of the process, but no endpoint does, and the files are never rewritten.

By design

Inventory has no time dimension

Records carry last_updated but no order_date, so filter_by_month() would match nothing. The month filter is deliberately not wired to /api/inventory.

Demo posture

No auth, open CORS

allow_origins=["*"] with credentials enabled, no rate limiting, and useAuth.js hardcodes isAuthenticated = true around a fixed user. Local development only, as the README states.
