System Architecture

Factory Inventory Management System

A full-stack inventory, order, and spending demo: a Vue 3 single-page app talking to a FastAPI backend that serves in-memory mock data loaded from JSON files — no database.

1Tech Stack

Frontend

Vue 3 SPA · Port 3000

  • Vue ^3.4.21 (Composition API)
  • Vue Router ^4.3.0
  • Axios ^1.6.7 (HTTP client)
  • Vite ^5.2.0 (dev server / build)
Backend

FastAPI Service · Port 8001

  • FastAPI ≥0.110.0
  • Pydantic ≥2.5.0 (validation)
  • Uvicorn ≥0.24.0 (ASGI server)
  • pytest ≥8.0.0 (backend tests)
Data

In-Memory Mock Data

  • Storage JSON files
  • Location server/data/*.json
  • Loader mock_data.py
  • Persistence none — resets on restart

3Request / Data Flow

1

User sets a filter

The FilterBar component updates shared reactive state in the useFilters composable (Time Period, Warehouse, Category, Order Status).

2

View requests data

A view (e.g. Dashboard.vue) calls getCurrentFilters() and passes the result into an api.js function such as api.getInventory(filters).

3

Axios builds the request

api.js converts filters into query params and sends a GET request to http://localhost:8001/api/….

4

FastAPI filters in memory

The route handler applies apply_filters() / filter_by_month() over the in-memory Python lists loaded from JSON at startup — no database is queried.

5

Pydantic validates the response

Results are coerced into typed Pydantic models (e.g. InventoryItem, Order) before being serialized back to JSON.

6

Vue re-renders via computed properties

Raw responses are stored in refs (allOrders, inventoryItems); derived values (totals, chart series) live in computed() so the UI updates reactively.

5Project Structure

client/              # Vue 3 + Vite SPA (port 3000)
├── src/
│   ├── views/         # Dashboard, Inventory, Orders…
│   ├── components/    # FilterBar, modals, nav
│   ├── composables/   # useFilters, useAuth, useI18n
│   ├── locales/        # en.js, ja.js
│   ├── api.js          # Axios client → backend
│   └── main.js
└── vite.config.js
server/              # FastAPI backend (port 8001)
├── main.py            # Routes + filtering logic
├── mock_data.py        # Loads JSON at startup
├── generate_data.py    # Sample data generator
└── data/
    ├── inventory.json
    ├── orders.json
    ├── demand_forecasts.json
    ├── backlog_items.json
    ├── purchase_orders.json
    ├── spending.json
    └── transactions.json
ⓘ No database. All data lives in JSON files under server/data/ and is loaded into memory once at startup by mock_data.py. Any writes (tasks, purchase orders) only mutate in-memory lists and reset when the server restarts.
