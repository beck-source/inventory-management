System Architecture

4 層。層をまたぐ通信は一箇所（client/src/api.js）に集約され、 バックエンドは単一モジュール server/main.py にすべてのルートを持つ。

Data Flow — フィルタ 1 回分の往復

4 つのフィルタ（Time Period / Warehouse / Category / Order Status）は全画面で共有され、 同じ経路をたどってサーバーのクエリパラメータになる。

ユーザーが FilterBar を操作する 選択値は composable のモジュールスコープに置かれた ref に書き込まれる。singleton なので全画面・全コンポーネントが同じ実体を参照する。 composables/useFilters.js — selectedPeriod / selectedLocation / selectedCategory / selectedStatus
画面が getCurrentFilters() でプレーンオブジェクトを取り出す selectedPeriod だけは API 都合で month というキーに詰め替えられる。ここが命名のずれる唯一の箇所。 views/*.vue
api.js がクエリ文字列を組む 値が 'all' のものは append せず落とす。結果として「全件」はパラメータの不在として表現される。 client/src/api.js — URLSearchParams
FastAPI が Optional なクエリパラメータとして受ける 未指定は None。ヘルパー側で None と 'all' はどちらも「絞り込まない」に畳み込まれる。 server/main.py — apply_filters() / filter_by_month()
メモリ上のリストを内包表記で絞り込む SQL もインデックスもない。最大でも 250 件のリスト走査なので、この規模では計算量が問題にならない。 server/main.py
Pydantic の response_model で検証してシリアライズ JSON の構造を変えると、ここでスキーマ不一致として顕在化する。 server/main.py — response_model=List[...]
画面が ref に格納し、computed が表示用データを導出する 合計・ソート・グルーピングはすべて computed 側。ref はサーバーから来た生データだけを保持する。 views/*.vue — allOrders / inventoryItems ほか

Observations

コードを読んで見つかった、現状のフロントとバックの食い違い。いずれも動作中のサーバーで確認済み。

Frontend / Backend 不整合 タスク機能のエンドポイントがバックエンドに存在しない

App.vue がマウント時に api.getTasks() を呼び、TasksModal.vue が 作成・削除・完了トグルを呼ぶが、main.py に /api/tasks は 1 つも登録されていない。 実際に GET /api/tasks は 404 を返す。エラーは console.error に 握り潰され、モーダルには useAuth のモックタスクだけが表示されるため、UI 上は破綻して見えない。

Frontend / Backend 不整合 発注（purchase order）はモデルだけあってルートがない

main.py は PurchaseOrder と CreatePurchaseOrderRequest を定義し、 purchase_orders を import しているが、使っているのは /api/backlog の has_purchase_order フラグ算出のみ。作成・参照のルートは未登録で、 POST /api/purchase-orders は 404 になる。 purchase_orders.json が空配列（0 件）なのもこれと整合する。

到達不能 Backlog.vue にルートが割り当てられていない

views/Backlog.vue（152 行）は存在するが、main.js のルート定義に含まれず、 どこからも import されていない。バックログの内容は Dashboard に埋め込まれたテーブルと BacklogDetailModal 経由で表示されている。

設定 CORS が全オリジン許可かつ credentials 有効

allow_origins=["*"] と allow_credentials=True の併用。 ローカル demo としては動くが、そのまま公開環境に出す構成ではない。

設計上の前提 書き込みは永続化されない

データはモジュールスコープの Python リストで、JSON への書き戻し経路がない。 仮にタスク／発注のルートを足しても、プロセス再起動で状態は初期化される。 デモとしては意図どおりだが、機能追加時にはこの前提を踏まえる必要がある。

定数 USD → JPY レートが 150 で固定

utils/currency.js の USD_TO_JPY = 150。表示通貨はロケール （en → USD / ja → JPY）に連動して切り替わるが、換算レートは静的な近似値。
