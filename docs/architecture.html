Request / Data Flow

1
FilterBar.vue
User adjusts one of 4 filters — Time Period, Warehouse, Category, Order Status — backed by the shared useFilters() composable (singleton refs).
2
views/*.vue
A view watches the active filters and calls the matching method on the centralized API client.
3
api.js
Builds a URLSearchParams query string and issues a GET (or POST/PATCH/DELETE) request to http://localhost:8001/api/* via axios.
4
main.py
FastAPI route handler receives optional query params and calls shared apply_filters() / filter_by_month() helpers.
5
mock_data.py
In-memory Python lists (loaded from JSON at startup) are filtered with list comprehensions — no query language, no indexes.
6
Pydantic models
Filtered results are validated and serialized against the endpoint's response_model before returning JSON.
7
computed()
The view stores the raw response in a ref (e.g. allOrders) and derives display data via Vue computed properties.

Key Patterns

Filters propagate via query params

The same 4 filters (period, warehouse, category, status) flow from useFilters() through every view into matching query params — filtering always happens server-side, in Python.

Raw refs, derived computed

Views keep unfiltered API responses in refs (allOrders, inventoryItems) and derive display data with computed(), matching the project's stated reactivity convention.

No database, no ORM

All entities live in JSON files under server/data/, loaded once by mock_data.py. Filtering is plain Python list comprehensions — fine at this data volume, not built to scale.

Schema enforced at the boundary

Pydantic models on each FastAPI route validate and shape responses, so the JSON data structure and the frontend's expectations stay in sync.
