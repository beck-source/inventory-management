Factory Inventory Management System

Vue 3 single-page app, FastAPI REST backend, in-memory mock data. No database.

System architecture

Three tiers, two processes. The browser talks to the API directly over HTTP.

Data flow

How a filter change becomes updated numbers on screen.

  1. Four shared filters (period, warehouse, category, order status) live as singleton refs in useFilters.js.
  2. A view calls api.* with getCurrentFilters(). Values of all are dropped from the query string.
  3. FastAPI filters the in-memory lists by warehouse, category, status, and month or quarter (matched on order_date).
  4. Pydantic validates the result, which is returned as JSON.
  5. The view stores raw data in refs (allOrders, inventoryItems) and derives chart and table data in computed properties.

Gaps found in the code

Observed while reading the source; useful to know before extending it.

  • api.js calls /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET), but main.py defines none of these routes. The CreatePurchaseOrderRequest model exists with no endpoint.
  • views/Backlog.vue is not imported by the router or any other file, so it is unreachable.
  • The API base URL is hardcoded to http://localhost:8001/api in api.js, and CORS allows every origin.
  • Quarter filtering is duplicated in main.py (QUARTER_MAP and inline checks in /reports/quarterly).
