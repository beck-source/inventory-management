Data flow

  1. User sets filters. FilterBar updates the shared refs in useFilters (period, warehouse, category, order status).
  2. View requests data. The view calls getCurrentFilters() and passes the result to a method in api.js, which turns it into query parameters.
  3. FastAPI receives the request. The endpoint reads the optional warehouse, category, status and month parameters.
  4. In-memory filtering. Helper functions filter the lists loaded from JSON; the dashboard summary aggregates totals (inventory value, low stock, pending orders).
  5. Validation and response. Pydantic validates the result and FastAPI returns JSON.
  6. Client renders. Raw data is stored in refs (for example allOrders, inventoryItems) and derived figures come from computed properties, so the UI updates when filters change.
Filter support differs by endpoint. Inventory accepts warehouse and category only (it has no time dimension). Orders and the dashboard summary accept all four filters. Demand, backlog and spending endpoints take no filters.
