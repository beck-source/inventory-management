Data Flow: A Filtered Request

What happens when a user changes a filter, for example Location = Tokyo on the Orders view.

1

FilterBar

User selects a value, which updates a singleton ref in useFilters

2

View watcher

View calls getCurrentFilters(): Location maps to warehouse, Period to month

3

api.js

Drops params equal to 'all' and sends a GET with query string

4

FastAPI route

apply_filters() then filter_by_month() run over in-memory lists

5

Pydantic

response_model validates and serializes the result to JSON

6

Computed

Raw data stored in a ref; KPIs, charts, and tables recompute

Request example

# Location = Tokyo, Period = Q2-2025, Status = all
GET /api/orders?warehouse=Tokyo&month=Q2-2025

# server/main.py
filtered = apply_filters(orders, warehouse, category, status)
filtered = filter_by_month(filtered, month)
# Q2-2025 -> ['2025-04','2025-05','2025-06']

Cross-cutting: locale and currency

The backend always returns USD. The client converts at display time based on locale.

// useI18n.js: locale persisted in localStorage
currentCurrency = locale === 'ja' ? 'JPY' : 'USD'

// utils/currency.js: fixed rate
formatCurrency(amount, 'JPY')  // amount x 150 -> ¥
t('dashboard.title')           // en.js / ja.js lookup

Known Gaps & Inconsistencies

Found while tracing the code. Worth knowing before building on these areas.

Broken

Frontend calls endpoints that don't exist

api.js defines task CRUD (/api/tasks) and purchase-order calls (/api/purchase-orders), but server/main.py has no such routes. The tasks modal and purchase-order creation will fail with 404/405.

Orphaned

Backlog view is not routed

views/Backlog.vue exists but isn't registered in main.js or linked in the nav, so it can't be reached.

Inconsistent

Reports bypasses the API client and filters

Reports.vue calls axios with hardcoded URLs instead of going through api.js, and ignores the global filter bar.

Hardcoded

Time periods are fixed to 2025

QUARTER_MAP and the quarterly report logic only recognize 2025 quarters. The yen rate is fixed at 150.

Hazard

Stale data generator

server/generate_data.py uses an old product catalog (Widgets, Bearings) and overwrites orders.json. Running it would desync orders from inventory and break tests.
