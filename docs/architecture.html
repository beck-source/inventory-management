Factory Inventory Management System

Architecture overview — Vue 3 SPA + FastAPI backend, in-memory demo data (no database)

Tech Stack

Frontend
  • Vue 3 — Composition API
  • Vite — dev server & bundler
  • Vue Router — client-side routing
  • Axios — HTTP client
Runs on localhost:3000
Backend
  • FastAPI — REST API framework
  • Pydantic — request/response validation
  • Uvicorn — ASGI server
Runs on localhost:8001 · docs at /docs
Data
  • Static JSON files in server/data/
  • Loaded into memory at startup
  • No database — changes don't persist
Loaded via server/mock_data.py

Key Patterns

Shared filter state

useFilters.js holds refs at module scope, so every component that imports the composable reads/writes the same singleton state — no prop drilling, no Pinia/Vuex needed for this scope.

Raw vs. derived data

Views keep server responses in plain refs (e.g. allOrders) and compute everything else — totals, chart series, filtered subsets — in computed() so it recalculates only when inputs change.

In-memory filtering

The backend has no database: apply_filters() and filter_by_month() in main.py filter Python lists on each request, then Pydantic validates the shape of the response.

Mock auth & i18n

useAuth.js returns a hardcoded current user (no login flow); useI18n.js swaps between en.js/ja.js locale files, and mock user data itself is language-aware.
