Factory Inventory Management System

Architecture overview · Vue 3 SPA + FastAPI + in-memory JSON data (no database)

System architecture

Tech stack

Frontend

  • Vue 3.4 (Composition API)
  • Vue Router 4 (history mode)
  • Axios 1.6
  • Vite 8 dev server, port 3000
  • Node ≥ 20.19 / 22.12
  • Custom SVG charts, CSS Grid; no UI library
  • i18n: English and Japanese

Backend

  • Python ≥ 3.11
  • FastAPI ≥ 0.110 + Uvicorn, port 8001
  • Pydantic ≥ 2.5 for validation
  • Package management with uv
  • Data: JSON files, no database

Tooling and tests

  • pytest, pytest-asyncio, httpx, pytest-cov
  • Tests in tests/backend/ (dashboard, inventory, misc endpoints)
  • scripts/start.sh and stop.sh start/stop both servers

Data flow

Request lifecycle

  1. The user changes a filter (period, warehouse, category, status) in FilterBar.
  2. The shared singleton state in useFilters updates, and getCurrentFilters() builds the query object.
  3. A view calls a method in api.js. Axios sends GET /api/...?warehouse=&category=&status=&month=. Values of all are omitted.
  4. A FastAPI route filters the in-memory list with apply_filters and filter_by_month. Quarters such as Q3-2025 expand to months.
  5. The response is validated against a Pydantic response_model and returned as JSON.
  6. The view stores raw data in refs, and computed properties derive totals and chart series.

Startup data load

When the server starts, mock_data.py reads every file in server/data/ into module-level lists. Routes read and filter these lists on each request, and no request writes to disk. A restart reloads the files, and generate_data.py can regenerate them.

Filter semantics

  • Inventory has no time dimension, so it ignores month.
  • Orders are filtered by order_date.
  • Category and status match case-insensitively.

Observations

  • Missing backend routes. client/src/api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, /{backlogItemId}). server/main.py defines no such routes, and the running server returns 404 for them. A PurchaseOrder model and purchase_orders.json exist, but nothing exposes them for writing.
  • Hard-coded API URL. The base URL is a constant in api.js. There is no Vite proxy or environment variable.
  • No auth. The user in useAuth.js is mock data, and CORS allows all origins. This is suitable for local demos only.
  • Large views. Dashboard.vue (about 1,270 lines) and Spending.vue (about 850 lines) hold most of the UI logic.
  • Test coverage. The backend tests cover dashboard, inventory and miscellaneous endpoints. There are no frontend tests.
