Request & data flow

  1. User changes a filter in FilterBar (time period, warehouse, category, order status) → updates shared refs in useFilters.js.
  2. Each view watch()es those refs and calls api.X(getCurrentFilters()) → {warehouse, category, status, month}.
  3. api.js builds a query string (drops values equal to all) and sends GET http://localhost:8001/api/….
  4. FastAPI route runs apply_filters() (warehouse exact; category/status case-insensitive) and filter_by_month() (date match; quarters like Q1-2025 expanded).
  5. Results are validated by Pydantic response models and returned as JSON.
  6. The view stores raw data in refs; computed properties derive KPIs, chart bars and tables.

Observations worth knowing

Frontend calls with no backend route

api.js calls /api/tasks (GET/POST/DELETE/PATCH) and /api/purchase-orders, but main.py defines only GET routes and neither path. PurchaseOrder models exist but are unused.

Unrouted view

views/Backlog.vue exists but the router (main.js) has no /backlog path.

Filter coverage is uneven

Demand and backlog endpoints take no filters; inventory ignores status/month. Demand and Backlog views cross-filter client-side against inventory.

Hardcoded API base

api.js hardcodes http://localhost:8001/api; Vite has no proxy, so the backend relies on permissive CORS.
