Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a stateless FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Three tiers, all running locally. The browser calls the API directly (no proxy), enabled by permissive CORS.

Data flow

How a filter change on the dashboard becomes updated numbers on screen.

  1. User changes a filterFilterBar updates the shared refs in useFilters (period, warehouse, category, status). Because they live at module level, every view sees the same state.
  2. View reactsA watch in the view (for example Dashboard.vue) fires and calls getCurrentFilters(), which maps the period to a month parameter.
  3. api.js builds the requestValues equal to all are dropped; the rest become query params, e.g. GET /api/orders?warehouse=...&month=Q3-2025.
  4. FastAPI filters in memoryThe handler calls apply_filters and filter_by_month over the lists loaded by mock_data.py. Quarters expand through QUARTER_MAP.
  5. Pydantic validates the responseEndpoints with a response_model serialize and validate before returning JSON. The dashboard summary and spending endpoints return plain dicts.
  6. View rendersRaw results are stored in refs (allOrders, inventoryItems); charts and KPI cards are computed properties, drawn with custom SVG and CSS Grid.

Things worth knowing

Observations from reading the code, not from running every feature.

Client calls routes the server does not define. api.js has methods for /api/tasks (get, create, delete, toggle) and /api/purchase-orders (create, get). main.py has no matching routes, although it defines a CreatePurchaseOrderRequest model. App.vue calls the task methods, so expect 404s there.
No persistence. Data is read once at startup. purchase_orders.json is empty, so every backlog item reports has_purchase_order: false.
Backlog.vue has no route. It exists in views/ but is not registered in main.js; backlog data reaches the UI through the Dashboard.
Hardcoded backend URL and open CORS. http://localhost:8001 is written into api.js and Reports.vue, and CORS allows every origin. Fine for a local demo, not for deployment.
Mock auth. useAuth returns a fixed user (with English and Japanese variants); there is no login or token handling.
