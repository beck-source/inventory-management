Data Flow

How a filter change on the dashboard becomes new numbers on screen.

  1. User changes a filterFilterBar updates shared refs in useFilters (period, location, category, status). The refs are module-level singletons, so every view sees the same state.
  2. View requests datagetCurrentFilters() maps the selection to warehouse, category, status, month. The view calls a method on api.js.
  3. API client builds the requestValues equal to all are dropped; the rest become query parameters on GET http://localhost:8001/api/....
  4. FastAPI filters in memoryapply_filters and filter_by_month run over the lists loaded from JSON at startup. No database is queried.
  5. Pydantic validates the responseEndpoints with a response_model are serialized and checked before returning JSON.
  6. Vue re-rendersThe view stores raw results in refs (such as allOrders, inventoryItems); totals and chart series are computed properties derived from them.

Observations

Gaps found while reading the code. Worth knowing before building on it.

  • api.js calls /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET), but main.py defines no such routes. A CreatePurchaseOrderRequest model exists with no endpoint using it. Those calls will return 404.
  • Backlog.vue exists but is not imported or registered in the router in main.js, so it has no URL.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js, and CORS allows all origins. Fine for a demo, not for deployment.
  • State is in memory and read-only per process, so there is no persistence across restarts.
