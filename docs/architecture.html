Data Flow

A user action in the browser turns into a filtered API request, runs against in-memory data, and comes back as reactive state that the views render.

User changes a filterWarehouse, category, status, or period in FilterBar
Shared filter stateuseFilters.js updates module-level refs
View reloads dataViews such as Dashboard.vue call api.js
FastAPI endpointQuery params are parsed and validated
In-memory filteringPython list comprehensions over the JSON data
Response modelPydantic shapes the JSON response
Computed propertiesViews derive charts and KPIs from the raw refs

Design Notes

  • No persistence. The server reads JSON once at startup. Changes made through the API are lost on restart.
  • Client-only state. Filters are shared through module-level refs in useFilters.js. The user profile and i18n locale are mock data, with the locale saved to localStorage.
  • Authentication is a stub. useAuth.js returns a fixed demo user. There is no login.
  • Reports bypasses the API client. Reports.vue calls axios directly instead of going through api.js.
  • Open CORS. allow_origins=["*"] is suitable only for local development.

Known Gaps

Missing endpoints The client calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders, but server/main.py does not define them. Verified: /api/tasks and /api/purchase-orders/1 return 404. Task errors are caught and logged to the console, so the UI does not show them.
Unused data purchase_orders.json is an empty array. Only the backlog flag has_purchase_order reads it.
Demo application. In-memory data, no authentication, not production-ready.
