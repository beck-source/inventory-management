The four shared filters — Time Period, Warehouse, Category, Order Status — are held as singleton refs in useFilters.js (selectedPeriod, selectedLocation, selectedCategory, selectedStatus) and mapped to { month, warehouse, category, status } query params. api.js omits any param set to 'all'. On the server, apply_filters() handles warehouse/category/status matching and filter_by_month() resolves both direct YYYY-MM values and quarter codes (Q1-2025–Q4-2025) against each record's date field.

Notable Details

No dev proxy

Vite has no proxy config. api.js hardcodes http://localhost:8001/api and relies on the server's permissive CORS policy (allow_origins=["*"]) rather than a same-origin proxy.

Fully in-memory data

mock_data.py loads JSON from server/data/ into module-level lists on startup. Any writes are non-persistent and reset when the server restarts.

Frontend/backend gap

api.js defines calls for /api/tasks and /api/purchase-orders (CRUD) that have no matching routes in main.py — likely a stubbed-out flow behind TasksModal.vue.

Note: This is a demo application — the wide-open CORS policy, hardcoded API base URL, and lack of persistence are appropriate for local development but would need to change before any production use.
