Factory Inventory Management System

A two-tier demo app: a Vue 3 single-page app on port 3000 calls a FastAPI service on port 8001, which serves mock factory data loaded from JSON files into memory at startup. It has no database, no auth, and no persistence.

System architecture

Three layers: browser client, API server, JSON files. All filtering happens in Python over in-memory lists.

Data flow: a filter change

What happens when a user changes the Warehouse filter on the Dashboard.

  1. User picks a warehouse in FilterBar

    FilterBar writes to selectedLocation, a module-level ref in useFilters.js. Because the refs live outside the function, every view shares one filter state.

  2. View watcher fires

    Dashboard.vue watches all four filter refs and calls getCurrentFilters(), which maps period to month and location to warehouse.

  3. Parallel API calls

    Promise.all over getDashboardSummary, getOrders, getInventory, getBacklog. api.js leaves out any param set to "all".

  4. FastAPI filters in memory

    apply_filters does exact matches on warehouse and case-insensitive matches on category and status. filter_by_month expands Q1-2025 style values via QUARTER_MAP and substring-matches order_date.

  5. Pydantic shapes the response

    Routes with a response_model validate and serialise. Summary, spending and reports return plain dicts.

  6. Reactive render

    Responses land in refs (allOrders, inventoryItems). Computed properties derive KPIs, chart series, and top products, and currency formatting follows the active locale.

Core data model

The Pydantic models in server/main.py. If you change the JSON shape, you have to update these models too.

InventoryItem

id, sku, name, category, warehouse, quantity_on_hand, reorder_point, unit_cost, location, last_updated

Order

id, order_number, customer, items[], status, order_date, expected_delivery, total_value, actual_delivery?, warehouse?, category?

DemandForecast

id, item_sku, item_name, current_demand, forecasted_demand, trend, period

BacklogItem

id, order_id, item_sku, item_name, quantity_needed, quantity_available, days_delayed, priority, has_purchase_order?

PurchaseOrder

id, backlog_item_id, supplier_name, quantity, unit_cost, expected_delivery_date, status, created_date, notes?

Derived metrics

Low stock: qty <= reorder_point. Pending: Processing + Backordered. Revenue goal: $800K per month, or $9.6M YTD.

Observations

Places where the code drifts from the intended pattern. Useful to know before you change anything.

Client calls endpoints the server does not defineapi.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders, but main.py has no such routes, so those calls return 404. CreatePurchaseOrderRequest is defined but never used.
Reports view bypasses the API clientReports.vue uses the Options API and hard-codes http://localhost:8001 with axios directly, instead of going through api.js.
Backlog.vue is orphanedThe view exists but is not registered in the router in main.js. Backlog data only shows up through the Dashboard.
Hard-coded configurationThe API base URL is fixed in api.js, quarters are fixed to 2025 in QUARTER_MAP, and CORS allows every origin. That's fine for a demo but not for deployment.
