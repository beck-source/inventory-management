Architecture Reference

Factory Inventory Management

Vue 3 + Vite FastAPI Python uv Pydantic In-Memory Data No Database
A dashboard for factory operations managers to monitor inventory health across warehouses in real time.

The app lets a manager slice six views — inventory levels, purchase orders, backlog, demand forecasts, spending, and a summary dashboard — by warehouse, product category, order status, and time period. Every view responds to the same four filters simultaneously, so a manager can instantly answer questions like "what's the backlog in Warehouse B for electronics this quarter?" without leaving the page.

Vue 3's reactivity model is what makes the filter-driven UI feel instant: raw data lives in refs, derived totals live in computed properties, and the whole page updates without round-trips for every widget. FastAPI serves that data from JSON files loaded once at startup — no database means no setup friction for a demo, and in-memory filtering is fast enough that the latency is invisible. The architecture is deliberately thin: it exists to show the UI patterns clearly, not to solve a production data problem.

Data Flow

1
User applies a filter
FilterBar.vue updates the useFilters composable — shared reactive state across all views.
2
Vue view triggers API call
api.js sends an Axios request with filter values as query params: warehouse, category, month, status.
3
FastAPI route receives and delegates
main.py extracts query params and passes them to mock_data.py for in-memory filtering.
4
Data is filtered and validated
Python filters the pre-loaded dataset. Results pass through Pydantic models for type validation before serialization.
5
Vue updates via computed properties
Raw data stored in ref(). All derived values (totals, summaries, filtered lists) live in computed() — never stored directly.

Key Patterns

Filter Propagation
Four global filters (Time Period, Warehouse, Category, Order Status) managed in useFilters and applied universally via query params on every request.
Reactivity Model
Raw API responses live in ref(). All derived data — totals, filtered lists, computed summaries — lives exclusively in computed(), never mutated directly.
No Database
All data is loaded from JSON files once at startup into Python memory. Filtering happens entirely in-process — no query language, no schema migrations.
Pydantic Boundary
Every API response is validated through a Pydantic model. Changing the JSON data structure requires a matching model update in main.py.
