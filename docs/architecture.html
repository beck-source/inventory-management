System Architecture

Factory Inventory Management System

A full-stack demo application: Vue 3 single-page frontend, a FastAPI backend, and in-memory JSON mock data — no database. Built for exploring inventory, orders, demand, and spending across warehouses.

API Endpoints

MethodPathFilters / Notes
GET/api/inventorywarehouse, category
GET/api/inventory/{item_id}single item, 404 if missing
GET/api/orderswarehouse, category, status, month (YYYY-MM or Q1-2025)
GET/api/orders/{order_id}single order, 404 if missing
GET/api/demandno filters
GET/api/backlogno filters; enriches items with has_purchase_order
GET/api/dashboard/summarywarehouse, category, status, month — aggregates KPIs
GET/api/spending/summary · /monthly · /categories · /transactionsno filters
GET/api/reports/quarterly · /monthly-trendsderived from in-memory orders
Known gap: the frontend (api.js) calls /api/tasks and /api/purchase-orders, but no matching routes exist in server/main.py. These calls are wrapped in try/catch, so the UI degrades gracefully rather than breaking.

Mock Data Files

inventory.json
Stock items — SKU, category, warehouse, quantity on hand, reorder point, unit cost
orders.json
Customer orders — line items, status, order date, delivery, warehouse, total value
demand_forecasts.json
Per-SKU current vs. forecasted demand, trend, period
backlog_items.json
Unfulfilled order lines — quantity needed vs. available, days delayed, priority
purchase_orders.json
POs raised against backlog (currently empty — no create endpoint wired up)
spending.json
Nested: spending summary, monthly spending, category spending
transactions.json
Recent financial transactions — date, category, warehouse, amount, vendor
Generated from a codebase investigation of the Factory Inventory Management System demo. No database — all state is rebuilt from JSON on server restart.
