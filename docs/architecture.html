Factory Inventory Architecture

A two-process demo: a Vue 3 single-page app talks to a FastAPI service over plain HTTP. There is no database and no ORM — seven JSON files are read into Python lists once at import time, and every request filters those lists in memory. Knowing that one fact explains most of the design decisions below.

System topology

Two independent processes, started separately. Nothing is shared between them except the HTTP contract — the SPA hardcodes the API origin rather than proxying through Vite.

Data flow

One mechanism drives nearly every screen: the four-filter round trip. The filters live in a module-scoped singleton, so changing a dropdown in the header re-reads data in whatever view happens to be mounted.

API surface

Thirteen routes, all GET. Filters are optional query parameters; an omitted parameter and the literal string all are treated identically.

Response models

Five Pydantic models gate the typed routes — InventoryItem, Order, DemandForecast, BacklogItem and PurchaseOrder. The spending and reports routes return bare dicts with no model, so changes to those JSON files pass through unchecked. Changing the shape of inventory.json or orders.json, by contrast, will fail loudly at request time until the matching model is updated.

Sharp edges

Things the code does not announce, each verified against the source rather than the docs.

The client calls seven endpoints the server does not define

api.js exports getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, targeting /api/tasks and /api/purchase-orders. Neither path exists in main.py.

App.vue calls getTasks() on mount; the 404 is swallowed by a catch that only logs, so the Tasks modal silently falls back to the mock tasks hardcoded in useAuth.js. The purchase-order methods are never called at all — purchase_orders.json is an empty array, so every backlog item reports has_purchase_order: false.

Nothing written at runtime survives a restart

mock_data.py runs json.load() at import and binds the results to module globals. Any mutation lives in that one process's memory and is never written back to server/data/. Adding real writes means deciding on persistence first, not just adding a POST route.

The backend understands quarters; the UI never sends them

filter_by_month() has a QUARTER_MAP covering Q1-2025 through Q4-2025, but FilterBar.vue only offers the twelve months of 2025. The quarter path is reachable only by calling the API directly. A quarter string outside the map falls through and returns the list unfiltered rather than empty.

The month filter cannot apply to inventory

Filtering keys off each record's order_date, and inventory items have no such field — only last_updated. So /api/inventory accepts warehouse and category only, and the dashboard's inventory figures ignore the time period dropdown while its order figures respect it.

CORS is wide open, with credentials

allow_origins=["*"] is paired with allow_credentials=True. That is fine for a local demo and wrong for anything deployed — browsers reject the combination, and the intent behind it is broader than this app needs.

Currency conversion is display-only

Switching to Japanese multiplies every figure by a constant 150 in utils/currency.js. The API always returns USD; nothing round-trips in yen, so JPY values are presentational and will not reconcile against the raw data.
