Factory Inventory Management System

Architecture overview — Vue 3 SPA, FastAPI backend, in-memory JSON data (no database)

Tech Stack

Frontend

Vue 3 + Vite

Composition API SPA, port 3000

  • Views: Dashboard, Inventory, Orders, Demand, Spending, Reports
  • vue-router — flat route table in main.js
  • Singleton composables as state (no Pinia/Vuex)
  • axios via api.js as the HTTP client
Backend

Python FastAPI

Single-file app, port 8001

  • Routes + Pydantic models in main.py
  • Shared filtering helpers reused across endpoints
  • Auto docs at /docs (Swagger UI)
Data

Static JSON, in memory

No database — no persistence

  • Loaded once at import via mock_data.py
  • 7 JSON files in server/data/
  • Edits reset on server restart

Data Flow — Example: Time Period Filter

1

User selects a month

In FilterBar.vue, a <select v-model="selectedPeriod"> binds directly to the shared useFilters() singleton ref — every view observes the same state.

2

View reacts

Dashboard.vue has a watch([selectedPeriod, ...], loadData) that fires on change and calls getCurrentFilters() to build the query params.

3

API client requests data

api.getDashboardSummary(filters) builds a URLSearchParams and issues GET /api/dashboard/summary?month=....

4

FastAPI filters in memory

get_dashboard_summary() runs apply_filters() and filter_by_month() over inventory_items / orders loaded by mock_data.py — no database query.

5

Response returns and re-renders

axios resolves into summary.value; downstream computed() properties (KPIs, order health, revenue goal) recompute and the template re-renders.

Notable Patterns

  • No database: all data is static JSON loaded once into memory on server start; changes don't persist and reset on restart.
  • Cross-view filter store: instead of Pinia/Vuex, a single composable (useFilters.js) holds shared refs that every view watches — a lightweight singleton store pattern.
  • Shared backend filtering: apply_filters() and filter_by_month() are reused across most endpoints rather than duplicating filter logic per route.
  • Loose frontend/backend contract: some API client methods have no matching route, so not every UI feature is backed by real data.
