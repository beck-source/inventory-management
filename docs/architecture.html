Architecture overview

Factory Inventory Management System

A two-tier demo app. A Vue 3 single-page app talks over REST to a FastAPI service. The service loads JSON files into memory at startup and filters them for each request. There is no database and nothing is persisted: writes, where they exist, only last until the process restarts.

Data flow: changing a filter

What happens when a user picks a warehouse, category, status or time period in the filter bar.

  1. User changes a filter components/FilterBar.vue

    The select is bound to a shared ref such as selectedLocation.

  2. Shared state updates composables/useFilters.js

    The four refs live at module scope, so every view sees the same values (a singleton without Pinia).

  3. The active view reacts views/*.vue → watch([...])

    Each view watches only the filters it supports. Dashboard and Orders watch all four, Inventory and Demand watch warehouse and category, and Spending watches only the period.

  4. API client builds the request api.js

    getCurrentFilters() maps the period to month, and api.js leaves out any value set to "all". Example: GET /api/orders?warehouse=Tokyo&month=Q2-2025.

  5. FastAPI filters in memory server/main.py

    apply_filters() matches warehouse exactly and category and status case-insensitively. filter_by_month() turns a quarter into its months and substring-matches order_date.

  6. Response validation response_model=List[...]

    Pydantic checks list endpoints against their models. The summary, spending and report endpoints return plain dicts that aren't validated.

  7. View recomputes and renders ref → computed → template

    Raw responses go into refs (allOrders, inventoryItems). KPIs, chart series and tables are computed properties, and amounts are formatted per locale (USD or JPY).

Observations

Things that stood out while reading the code. Worth knowing before you extend it.

Frontend calls endpoints the backend doesn't have

api.js defines task and purchase-order calls, but main.py has no matching routes, so the Tasks modal and purchase-order creation will get 404s.

Backlog view isn't routed

views/Backlog.vue exists, but main.js doesn't register a route for it. Backlog data is shown on the Dashboard through BacklogDetailModal.

Reports bypasses the API client

Reports.vue calls http://localhost:8001 through axios directly, so the base URL is defined in two places.

Time filtering is fixed to 2025

QUARTER_MAP and the quarterly report logic hard-code 2025 months, and month filtering uses substring matching on the date string.

Demo-grade by design

The app has no database, no real authentication (useAuth returns a fixed user), and CORS is open to *. That's fine for a local demo, but all three would need work before production.
