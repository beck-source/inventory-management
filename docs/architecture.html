Factory Inventory Management System

A demo full-stack application: a Vue 3 single-page app talking to a FastAPI backend that serves in-memory data loaded from JSON files. There is no database.

System architecture

The client calls the API directly at http://localhost:8001/api (hard-coded in client/src/api.js); Vite only serves the static app.

Data flow

  1. User changes a filter

    Four shared filters (period, warehouse, category, order status) live as singleton refs in useFilters.js, so every view sees the same state.

  2. View builds the request

    getCurrentFilters() maps the period to a month value. api.js drops any filter set to all before sending the query string.

  3. FastAPI filters in memory

    apply_filters matches warehouse, category and status (category and status case-insensitively). filter_by_month matches a month or a quarter such as Q1-2025 against order_date.

  4. Response is validated

    List endpoints return Pydantic response_models. The dashboard summary computes inventory value, low-stock count, pending orders and backlog count on the fly.

  5. View renders derived data

    Raw responses are stored in refs (for example allOrders, inventoryItems). Charts and tables are computed properties built from them.

Known gaps found while reviewing

Client calls endpoints the server does not define. api.js calls /api/tasks (get, create, delete, toggle) and /api/purchase-orders (create, get by backlog item). server/main.py has no such routes; purchase orders are only read from JSON to set the backlog flag. These calls would return 404 against the current backend.

views/Backlog.vue exists but is not registered in the router; backlog items are shown inside the Dashboard instead.
