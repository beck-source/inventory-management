Architecture overview

Factory Inventory Management System

A demo full-stack app: a Vue 3 single-page app talks over HTTP/JSON to a Python FastAPI service. The service loads JSON files into memory at startup and filters them on every request. There is no database, and nothing you change is persisted.

System architecture

Tech stack

Frontend
  • Vue 3 with the Composition API
  • vue-router 4, history mode
  • axios for HTTP
  • Vite 8 dev server and build, port 3000
  • Hand-written SVG charts and CSS Grid; no UI or chart library
  • Built-in i18n (English / Japanese), with USD/JPY switching
Backend
  • Python 3.11+
  • FastAPI, served by Uvicorn on port 8001
  • Pydantic v2 validates responses
  • Automatic OpenAPI docs at /docs
  • Dependencies managed with uv (pyproject.toml)
Data and testing
  • 7 JSON files in server/data/ (generated by generate_data.py)
  • No database; data is held in memory and resets on restart
  • pytest with FastAPI TestClient in tests/backend/
  • No frontend unit tests; browser checks are done with Playwright MCP

Data flow: changing a filter

  1. The user picks a value in FilterBar (Time Period, Warehouse, Category, Order Status).
  2. That value is written to a module-level ref in useFilters.js. The refs live outside the function, so every view shares one filter state.
  3. The active view watches those refs and calls getCurrentFilters(), which maps Location to warehouse and Period to month.
  4. api.js leaves out any filter set to "all" and sends, for example, GET /api/orders?warehouse=Tokyo&month=Q3-2025.
  5. FastAPI runs apply_filters() and then filter_by_month() over the in-memory list. Matching is case-insensitive and works on copies, so the source data is never changed.
  6. Pydantic validates the result against response_model and returns it as JSON.
  7. The view stores the raw rows in refs such as allOrders and inventoryItems. KPIs, charts and tables are computed properties built from those refs.

Things worth knowing

Missing endpoints. api.js calls /api/tasks and /api/purchase-orders, but main.py defines neither, so those calls return 404. The PurchaseOrder model exists, but purchase_orders.json is empty.
Unrouted view. Backlog.vue exists but isn't registered in the router. Backlog data only appears on the Dashboard.
Inconsistent client. Reports.vue calls axios with a hard-coded URL instead of going through api.js.
Year is hard-coded. The quarter mapping and the FilterBar month options only cover 2025.
Demo-only security. There is no authentication (useAuth is a mock user), CORS allows every origin, and there is no rate limiting.
