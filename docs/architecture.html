Architecture Reference

Factory Inventory Management System

A demo full-stack analytics dashboard. A Vue 3 single-page application talks cross-origin to a read-only Python FastAPI service that serves seven static JSON files loaded into memory once at import time. There is no database and no persistence layer.

Vue 3 SPA :3000 FastAPI :8001 14 GET endpoints In-memory JSON 40 backend tests

Read-only by construction. mock_data.py exposes one function, load_json_file(), called at import to populate module-level globals. There is no cache layer, no reload, and no write path — every request serves the same in-memory lists, so any mutation is lost on restart and data resets to the JSON on disk.

03Data Flow — One Filter Change, End to End

The filter bar is the spine of the application. It renders once in App.vue above <router-view>, so it survives navigation, and each view independently watches the slice of filter state it cares about.

User changes a select in FilterBar.vue

Four <select> elements are v-model-bound directly to shared refs — there is no local copy and no emit.

useFilters.js singleton refs mutate

selectedPeriod, selectedLocation, selectedCategory, selectedStatus are declared at module top level, so ES module caching makes every caller share one instance — a de-facto store without a store library. Default is the sentinel 'all'.

Each mounted view's watch fires

Views subscribe selectively: Dashboard and Orders watch all four refs; Inventory, Demand and Backlog watch only location and category (inventory has no time dimension); Spending watches only period; Reports watches nothing.

getCurrentFilters() renames to API keys

UI names map to backend names — selectedLocation → warehouse, selectedPeriod → month — and month is omitted entirely when it is 'all'.

api.js builds the query string

URLSearchParams plus a repeated guard: a param is appended only when the value is truthy and not 'all'. The result is concatenated onto the hardcoded base URL.

FastAPI filters in memory

apply_filters() matches warehouse exactly but lowercases category and status; filter_by_month() substring-matches order_date, expanding Q1-2025-style values through QUARTER_MAP. Both are defined in main.py, not in mock_data.py.

Pydantic validates the response

Six list/item endpoints declare a response_model; the eight aggregate and spending endpoints return raw dicts with no model, so their shape is unvalidated.

Vue stores raw data in refs, derives the rest

Responses land in refs such as allOrders and inventoryItems; every KPI, chart series and table is a computed property over them. Views never mutate fetched data in place.

08Notable Findings

Surfaced while tracing the call graph. Listed for orientation — nothing here has been changed.

Six api.js methods call endpoints that do not exist Broken

api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem against /api/tasks and /api/purchase-orders. Neither path is registered in main.py — confirmed against all 14 route decorators. App.vue calls the four task methods on mount and from its task UI, so those requests 404. The task list still renders because a computed property merges the failed API result with a hardcoded mock user's tasks, which masks the failure.

Dashboard.vue renders a component that does not exist Broken

The template references <PurchaseOrderModal>, but no such file exists in client/, and it is neither imported nor declared in the components block. Its supporting state (showPOModal, poModalMode, openPOModal) is fully implemented in setup() — this looks like a feature whose modal was never committed.

Backlog.vue is a complete orphan Dead code

A finished view — stat cards, table, filter wiring — with no route pointing at it and no import anywhere. The backend /api/backlog endpoint it targets is live and is used by Dashboard.vue.

Purchase-order feature is scaffolded but inert end to end Dead code

PurchaseOrder and CreatePurchaseOrderRequest models exist but no route uses them; purchase_orders.json is an empty array, so the computed has_purchase_order flag is always false. The unreachable frontend modal above is the third piece of the same unfinished feature.

Hardcoded values sit alongside live data Demo artifact

Several Dashboard.vue KPIs are literals rather than derived from the API — inventory turnover, and an orders goal of { fulfilled: 187, goal: 200 }. utils/currency.js hardcodes USD_TO_JPY = 150. Expected for a demo, but worth knowing before trusting a number on screen.

No dev proxy; CORS is wide open Config

vite.config.js sets only port: 3000 — no server.proxy. The base URL is hardcoded to http://localhost:8001/api in api.js and again inline in Reports.vue, so the app is not deployable behind a single origin without edits, and the backend compensates with allow_origins=["*"] plus allow_credentials=True.
